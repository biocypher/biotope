    CLI reference¶

    Run each command from the project folder as uv run --project graph biotope …. Commands that write a report take --json and then write one JSON document to stdout.

    biotope¶

    Biotope is a framework that helps AI agents build and maintain purpose-driven knowledge representations.

    Usage:

    biotope [OPTIONS] COMMAND [ARGS]...

    Options:

    Name Type Description Default
    --version boolean Show the version and exit. False
    --help boolean Show this message and exit. False

    Subcommands

    • add: Describe data files or folders as datasets, and create the annotation file of each.
    • annotate: Write what people know about a dataset into its annotation file, and validate descriptions.
    • check-data: Compare the data files with the SHA-256 checksums their descriptions record, and report each changed file.
    • config: Manage the project metadata that biotope add applies to every dataset.
    • extract: Extract records from documents with the extractions listed in graph/extraction.
    • graph: Scaffold, check, assess, visualize or build one graph workspace.
    • init: Create a Biotope project in the folder NAME, or in the current folder with NAME ".".
    • map: Record the project's purpose and inspect Croissant metadata.
    • mark: Set the biotope:status of DATASET to STATUS.
    • mv: Move a tracked file or directory and update every description and source package that names it.
    • queue: Show every dataset grouped by its status: raw, processed or mapped.
    • rm: Remove a dataset or a file from Biotope, with its data unless --keep-data is given.
    • source: Register authored descriptions and scaffold project-owned source packages.
    • status: List the dataset manifests in .biotope/datasets and mark those whose revision differs from the one their source package in graph/sources pins.

    add¶

    Describe data files or folders as datasets, and create the annotation file of each.

    Usage:

    biotope add [OPTIONS] [PATHS]...

    Options:

    Name Type Description Default
    --rebake boolean Describe an already-tracked dataset again from its data and annotation file False
    --json boolean Emit a complete machine-readable scan report on stdout False
    --name text Dataset name override None
    --description text Dataset description override None
    --license text Dataset license None
    --creator text Dataset creator name None
    --creator-email text Dataset creator email None
    --url text Dataset URL None
    --citation text Dataset citation text None
    --version text Dataset version None
    --keyword text Dataset keyword (repeatable) None
    --access-restrictions text Dataset access restrictions None
    --legal-obligations text Dataset legal obligations None
    --collaboration-partner text Dataset collaboration partner None
    --rai text Croissant RAI field as KEY=VALUE None
    --status choice (raw | processed) Override workflow state. Default: 'processed' when fields are described, 'raw' otherwise. This does not validate values. None
    --derived-from text Record this dataset as derived from another (repeatable). Pass a dataset reference — data path, manifest path, or dataset name. None
    --help boolean Show this message and exit. False

    annotate¶

    Write what people know about a dataset into its annotation file, and validate descriptions.

    Usage:

    biotope annotate [OPTIONS] COMMAND [ARGS]...

    Options:

    Name Type Description Default
    --help boolean Show this message and exit. False

    Subcommands

    • set: Write KEY=VALUE pairs into the annotation file of DATA, a dataset biotope add described.
    • validate: Validate a Croissant metadata file.

    set¶

    Write KEY=VALUE pairs into the annotation file of DATA, a dataset biotope add described.

    Without --table the values describe the dataset, with --table that table, and with --column that column. A repeated KEY makes a list, and an empty VALUE clears what the data says. A table's key names its columns, as in key=person_id; an equivalent property is a URL, as in equivalentProperty=https://schema.org/name.

    Usage:

    biotope annotate set [OPTIONS] DATA VALUES...

    Options:

    Name Type Description Default
    --table text A table's ID as biotope map inspect prints it, such as push/people.csv#people. None
    --column text A column of --table, by its name in the data. None
    --help boolean Show this message and exit. False

    config¶

    Manage the project metadata that biotope add applies to every dataset.

    Usage:

    biotope config [OPTIONS] COMMAND [ARGS]...

    Options:

    Name Type Description Default
    --help boolean Show this message and exit. False

    Subcommands

    • set-project-metadata: Set project metadata in .biotope/config.yaml. Give only values the user confirmed for every dataset; a dataset's annotation file overrides them. An empty value removes the field.
    • show-project-metadata: Show the project metadata that biotope add applies to every dataset.

    set-project-metadata¶

    Set project metadata in .biotope/config.yaml. Give only values the user confirmed for every dataset; a dataset's annotation file overrides them. An empty value removes the field.

    Usage:

    biotope config set-project-metadata [OPTIONS]

    Options:

    Name Type Description Default
    --description text What the project is about. None
    --url text The project's web page. None
    --creator text The contact person for every dataset, when the user names one for the project. None
    --license text The license URL of every dataset. None
    --citation text How to cite every dataset. None
    --access-restrictions text Access restrictions of every dataset. None
    --legal-obligations text Legal obligations of every dataset. None
    --collaboration-partner text The collaboration partner and institute. None
    --help boolean Show this message and exit. False

    extract¶

    Extract records from documents with the extractions listed in graph/extraction.

    Usage:

    biotope extract [OPTIONS] COMMAND [ARGS]...

    Options:

    Name Type Description Default
    --help boolean Show this message and exit. False

    Subcommands

    • run: Run the extractions NAMES, or every listed extraction, store their records in data/extracted/NAME.jsonl and register each as a processed dataset. Records mirror the files the extraction's patterns match now; unchanged documents reuse their stored records.
    • try: Run the extraction NAME on FILES and show the records with their evidence. Nothing in the project changes.

    run¶

    Run the extractions NAMES, or every listed extraction, store their records in data/extracted/NAME.jsonl and register each as a processed dataset. Records mirror the files the extraction's patterns match now; unchanged documents reuse their stored records.

    Usage:

    biotope extract run [OPTIONS] [NAMES]...

    Options:

    Name Type Description Default
    --redo file Extract this document again although its inputs are unchanged; repeatable None
    --json boolean Write one JSON report to stdout False
    --help boolean Show this message and exit. False

    try¶

    Run the extraction NAME on FILES and show the records with their evidence. Nothing in the project changes.

    Usage:

    biotope extract try [OPTIONS] NAME FILES...

    Options:

    Name Type Description Default
    --json boolean Write one JSON report to stdout False
    --help boolean Show this message and exit. False

    graph¶

    Scaffold, check, assess, visualize or build one graph workspace.

    Usage:

    biotope graph [OPTIONS] COMMAND [ARGS]...

    Options:

    Name Type Description Default
    --help boolean Show this message and exit. False

    Subcommands

    • build: Run loaders, mappings and quality checks, then export the graph.
    • check: Check definitions and Python types without invoking loaders or mappings.
    • metagraph: Write an offline viewer of the topology; --report adds the counts of a build.
    • quality: Run project loaders and mappings; print measurements of the Python graph objects without export.
    • scaffold: Create graph boilerplate without scanning data or executing a pipeline.

    build¶

    Run loaders, mappings and quality checks, then export the graph.

    Usage:

    biotope graph build [OPTIONS]

    Options:

    Name Type Description Default
    --graph path Graph workspace; defaults to graph/ in the current directory. graph
    --json boolean Emit one structured report to stdout. False
    --out path Build directory; defaults to build/ in the graph workspace, which a build replaces. None
    --format choice (csv | parquet | sqlite) Neo4j import files through BioCypher (csv, parquet), or one SQLite database (sqlite). csv
    --help boolean Show this message and exit. False

    init¶

    Create a Biotope project in the folder NAME, or in the current folder with NAME ".".

    Writes the project's purpose to .biotope/project.yaml, and a root .gitignore when the project has none.

    Usage:

    biotope init [OPTIONS] [NAME]

    Options:

    Name Type Description Default
    --dir, -d directory The folder that holds NAME; the current folder by default. .
    --purpose, -p text The project's purpose: who uses the graph, for which tasks, and the typical questions. Without it, init asks in a terminal. None
    --no-prompt boolean Never ask; without --purpose, the purpose stays empty. False
    --interactive boolean Open project.yaml in $EDITOR to write the purpose. False
    --help boolean Show this message and exit. False

    queue¶

    Show every dataset grouped by its status: raw, processed or mapped.

    Also lists each prov:wasDerivedFrom entry that names no dataset.

    Usage:

    biotope queue [OPTIONS]

    Options:

    Name Type Description Default
    --status choice (raw | processed | mapped) Show only one section. None
    --json boolean Write one JSON report to stdout. False
    --sort choice (time | name) Order within each section. 'time' picks the oldest raw first. time
    --help boolean Show this message and exit. False

    rm¶

    Remove a dataset or a file from Biotope, with its data unless --keep-data is given.

    A dataset's path removes its data and its description. A file's path removes the file from its dataset's description, and the description goes when no file is left.

    Usage:

    biotope rm [OPTIONS] TARGET

    Options:

    Name Type Description Default
    --keep-data boolean Keep the data on disk. False
    --force, -f boolean Skip the confirmation prompt. False
    --help boolean Show this message and exit. False

    source¶

    biotope source [OPTIONS] COMMAND [ARGS]...

    Options:

    Name Type Description Default
    --help boolean Show this message and exit. False

    Subcommands

    • generate: Reconcile one manifest with its source packages; create only what is missing.
    • register: Register an authored Croissant description of data no bake describes.

    generate¶

    Reconcile one manifest with its source packages; create only what is missing.

    Every described RecordSet, and every file no RecordSet reads, gets a package with a schema, a registration and a placeholder loader. Existing schemas, registrations and loaders are never rewritten. Drift, orphans and conflicts are reported; on a conflict nothing is written.

    Usage:

    biotope source generate [OPTIONS] METADATA

    Options:

    Name Type Description Default
    --out directory Sources package, e.g. graph/sources. _required
    --package text Root package for this manifest; defaults to the root that holds it, else the manifest filename. None
    --check boolean Report what generation would change, without writing. False
    --help boolean Show this message and exit. False

    register¶

    Usage:

    biotope source register [OPTIONS] METADATA

    Options:

    Name Type Description Default
    --name text Managed dataset name/path, without .jsonld. _required
    --help boolean Show this message and exit. False
